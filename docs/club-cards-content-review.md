# Картки клубу та пакетні дії — 22.10.2026

## Погоджена поведінка

Картка клубу відзначає цінний для клубу вчинок або поведінку. У тренуванні
спочатку зберігають присутність, за потреби вносять картки, потім підтверджують
завершення обліку. Обмеження за часом внесення відсутні. На гравця й тренування
може бути одна чинна картка клубу. Повтор запиту повертає той самий запис.
Помилкову картку можна анулювати з причиною; аудит зберігається.
Профіль показує тільки загальну кількість чинних карток клубу. Історія,
дати й коментарі клубних карток у профілі не показані. Жовті картки та
правило участі в «Зірці місяця» залишаються окремими.

Адміністратор може пакетно вилучати вибрані або всі активні навчальні завдання
й терміни. Це деактивація, а не фізичне видалення: історичні зв'язки
тренувань збережені, неактивні записи доступні у відповідному перегляді.
Імпорт підтримує додавання та повну заміну поточного переліку. Заміна
перевіряє версії всіх активних рядків, показує стару й нову кількість,
виконує деактивацію та імпорт в одній транзакції. Помилка відновлює попередній
стан автоматично. Застарілий або повторний запит відхиляється.
Пакетні операції вимагають чинного адміністратора з AAL2; тренеру вони недоступні.

## Ізольована контрольна версія

Тестові екрани використовують компоненти цього editable source та ті самі
PostgreSQL RPC/RLS. PGlite 0.5.11 виконує SQL у браузері. Всі профілі,
гравці, групи та події вигадані; немає URL або ключів робочого Supabase.
Дані зберігаються в IndexedDB конкретного браузера. В іншому браузері
буде окрема початкова тестова база. Не вводьте тут персональні дані.

Відкрити «Облік тренування», зберегти присутність, відзначити гравця карткою
клубу, завершити облік. У «Профілі гравця» перевірити лічильник. У «Завданнях»
і «Словнику» перевірити вибір, скасування підтвердження та пакетне вилучення.
В «Імпорті» доступні вигадані CSV для нових завдань U6–U17 та словника.
Оберіть набір, позначте повну заміну, завантажте CSV, перевірте й підтвердіть.

Це огляд погоджених змін, а не повний клон усіх модулів. Вхід тренера й
адміністратора тут імітується локальними ролями. Справжній Supabase Auth,
MFA, Storage та Edge Functions не перевіряються. Excel/Word у робочому
імпортері збережені; контрольний режим використовує CSV, оскільки не має
окремого Supabase Edge-сервера. Це не повне recovery-відновлення.

## Відтворення перевірки

1. `npm ci` (потрібен Node >=22.13).
2. `npm run quality` — ESLint, TypeScript, Node-тести, static build.
3. В окремій директорії QA: `npm install --no-save @electric-sql/pglite@0.5.11 esbuild@0.28.2`.
4. `node scripts/verify-club-cards-content.mjs /ABS/QA/node_modules/@electric-sql/pglite/dist/index.js`.
5. `node scripts/verify-release-integration.mjs /ABS/QA/node_modules/@electric-sql/pglite/dist/index.js`.
6. `node scripts/build-review-preview.mjs /ABS/QA/node_modules/esbuild/lib/main.js /ABS/QA/node_modules/@electric-sql/pglite/dist/index.js`.
7. Обслуговувати `review-dist/` статичним сервером; для віддаленого доступу потрібен HTTPS.

Перевірено: 125 Node-тестів, ESLint/TypeScript/build, 46 нових SQL-перевірок,
1654 assertions повної сумісної схеми (36 звірених історичних файлів + 8 пропозицій,
47 таблиць із RLS). Ці числа не є кількістю незалежних E2E-сценаріїв.
У браузері перевірено збереження присутності, картку клубу, завершення обліку,
лічильник без клубної історії, скасування й вибіркове вилучення завдань,
повну заміну трьох завдань U6–U17, вилучення всіх термінів і їх заміну CSV.

## Порядок майбутнього випуску

Обидва нові SQL-файли залишаються UNAPPLIED у `supabase/proposals/`:
- `20261022181735_club_cards.sql` після пропозиції обліку тренування;
- `20261022181737_bulk_content_management.sql` після пропозиції incremental import.

До випуску потрібні окреме погодження, повний захищений backup, контрольне
відновлення, справжні admin/coach login і перевірка паралельних PostgreSQL-сесій.
Історичний `20260920085722_cleanup_transient_schedule_conflicts.sql` не застосовувати,
журнал міграцій не виправляти автоматично. Не виконувати blanket `db push`.
Frontend вимагає сумісної серверної схеми; окремо його у чинну версію не випускати.
Зашифрований JSON застосунку доповнено `player_club_cards` (формат 1.6, 47 таблиць),
він не замінює повний PostgreSQL/Auth/Storage backup.
