# Перевірка версії 0.2.1

Дата локальної перевірки: 17 вересня 2026 року.

## Усунені розбіжності

| Ділянка | Результат |
|---|---|
| План адміністратора | Операційний запис відкриває пов’язану подію; адміністратор змінює час, майданчик, основного тренера, заміну й стан. |
| Перенесення | Первинний час і ознака перенесення встановлюються тригером; кожне перенесення створює окрему операційну дію. |
| Присутність | Усі записи сесії зберігає одна SQL-транзакція; неповний склад відхиляється, а застаріла офлайн-черга не перезаписує новіші дані. |
| Форма | Тренер не змінює запит у стані «Готується» або «Видано»; запит і позиції зберігаються атомарно; адміністратор має фільтр і керування каталогом. |
| Методика | Завдання й структури можна редагувати, впорядковувати, активувати та деактивувати. |
| Інвентар | Позиції можна деактивувати; масові й індивідуальні дозволи розділено; тренер не може сам деактивувати позицію. |
| Файли | Клієнт створює лише `pending`; сервер перевіряє тип, сигнатуру, розмір, активний вміст і SHA-256; лише `clean` доступний через Storage. |
| Імпорт | CSV підтримує лапки й переноси; є перевірка значень і дублікатів; підтвердження всіх рядків виконує одна MFA-транзакція. |
| Користувачі | Мінімум 12 символів, обов’язкова зміна тимчасового пароля, MFA для адміністративних операцій, атомарне призначення команд. |
| Резервування | Адміністративний JSON шифрується AES-256-GCM; додано перевірену команду розшифрування та регламент відновлення. |

## Автоматичні перевірки

- `npm run lint` — пройдено без попереджень.
- `npm run typecheck` — пройдено.
- `npm test` — 26 тестів пройдено.
- `npm run build` — production-збірка Next.js пройдена.
- `git diff --check` — має виконуватись перед передачею архіву.

## Перевірка бази

Додано 3 набори pgTAP-тестів, включно з RLS, MFA, блокуванням форми, інвентарем, перенесенням події та серверним станом файлів. У поточному середовищі немає запущеного Docker/PostgreSQL на `127.0.0.1:54322`, тому `npm run db:test` тут не виконався. Перед staging-розгортанням обов’язково запустити:

```bash
npx supabase start
npx supabase db reset
npm run db:test
```

## Готовність staging

17 вересня 2026 року виконано повторну перевірку перед staging:

- чинний Sites-проєкт залишається приватним і доступ не розширено;
- чинна опублікована версія не замінювалась;
- окремі staging-змінні Supabase у середовищі відсутні;
- `SUPABASE_ACCESS_TOKEN` не налаштований;
- Docker/PostgreSQL для локального запуску pgTAP у середовищі відсутній.

Наступний технічний крок — підключити окремий staging-проєкт Supabase. Після цього застосувати міграції, розгорнути Edge Functions, виконати pgTAP/RLS-тести й лише тоді створювати приватну staging-версію frontend.

## Межа цього етапу

Production і чинний приватний Sites-сайт не змінювались. Міграції, Edge Functions і новий frontend слід спочатку розгорнути в окремому staging-середовищі, пройти pgTAP та ручні рольові сценарії й лише після окремого підтвердження власника замінювати чинний приватний сайт.
