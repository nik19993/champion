# Клуб Чемпіон — робочий застосунок 0.2.24

Це повний редагований вихідний проєкт застосунку Клубу Чемпіон, відновлений з погодженого прототипу та послідовно оновлений у source. Поточна staging-збірка розгортається лише приватно; production не змінюється без окремого підтвердження власника.

## Уже реалізовано

- Next.js + TypeScript із статичним export для Sites;
- адаптивна жовто-чорна дизайн-система, надана емблема клубу та заголовок лише «ЧЕМПІОН»;
- реальний email/password-вхід через Supabase Auth;
- відновлення пароля;
- обов’язковий TOTP/MFA для адміністратора;
- базові таблиці профілів, груп і призначень тренерів;
- 25 повноцінних груп: U6, U7, U8A–U17B та «Воротарі A/B/C»;
- призначення одного тренера до однієї або кількох вікових чи воротарських груп;
- календар тренера з часом за Києвом, події всіх закріплених команд, відвідування до/під час/після події та офлайн-черга; після присутності тренування одразу відкривається окремий крок жовтих карток без втрати контексту події; редактор події автоматично відновлює незбережену чернетку;
- гравці з пріоритетним показом контактів батьків одразу після фото й основної інформації, оплати лише «оплачено»/«не оплачено», коротка характеристика тренера та форма; текстові зміни й запити форми мають локальні чернетки;
- методика: пошук і редагування термінів, програма занять, структура тренування та довільні розділи загальної методичної бібліотеки;
- 318 погоджених навчальних завдань вихідної програми U6–U15 (програма U15 є старшою базою для U15–U17) і 110 термінів у відтворюваному seed;
- керовані адміністратором довідники тестування фізичної підготовленості та складових ігрової діяльності, а також сумісний Excel-імпорт результатів із датою в таблиці або спільною датою в інтерфейсі;
- інвентар груп із незалежними дозволами на кількість та втрати/придбання, чітким станом збереження, локальним відновленням змін і скасуванням останнього збереження;
- адміністративні План, Групи, Форма, Керування, звіти, імпорт і експорт; наявні поля та майданчики можна редагувати, зміни форми мають виразний стан збереження й скасування; PDF-звіти завантажуються як файли, а за відсутності записів містять повідомлення «Дані не внесено»;
- пакетний імпорт CSV/XLSX/DOCX підтримує гравців, фізичні тести, ігрову діяльність, навчальні завдання й термінологію; в інтерфейсі є універсальні шаблони Excel і Word;
- оголошення можна адресувати окремим тренерам, віковим категоріям або конкретним групам, включно з «Воротарі A/B/C»;
- «Зірка місяця»: спільна тема для всіх груп, централізований перелік причин і анулювання помилкових жовтих карток лише для тренувань, контроль контакту з батьками, автоматичний недопуск після чотирьох карток і два різні переможці з єдиною назвою нагороди без загального рейтингу;
- експорт нагород за місяць в один PDF: дві вертикальні нагороди A5 для переможців групи на одному горизонтальному аркуші A4, автоматичне фото з профілю та повне блокування експорту з точним переліком гравців без фото; службова графіка вбудована у генератор і не залежить від окремих мережевих запитів;
- окремі дії «Заборонити доступ» і «Видалити тренера»; остаточне видалення прибирає Auth-акаунт, але зберігає історичні записи та передає майбутні події на перепризначення;
- RLS: тренер бачить лише призначені групи, адміністратор — усі після MFA;
- приватні Storage buckets;
- SQL RLS-тести, контрактні тести, lint, typecheck і CI;
- перевірена staging-база з мінімальними Data API-правами та індексами всіх зовнішніх ключів;
- згенеровані типи staging-схеми підключені до Supabase-клієнта;
- попередження та автоматичний вихід після 30 хвилин бездіяльності;
- окремі конфігурації staging та production без автоматичного deploy;
- відтворюваний і повністю видалюваний набір синтетичних staging-даних без адрес, телефонів чи доступного для входу тестового облікового запису.

## Локальний запуск

Вимоги: Node.js 22.13+; для локального Supabase також Docker.

```bash
npm ci
cp .env.example .env.local
npx supabase start
npx supabase db reset
npm run dev
```

Після старту локального Supabase вставити локальні URL та publishable key у `.env.local`.

## Перевірка

```bash
npm run lint
npm run typecheck
npm run test
npm run build
npm run db:test
```

`db:test` потребує запущеного локального Supabase. Команда `npm run quality` виконує всі перевірки, які не потребують Docker.

## Перший адміністратор

Після створення першого користувача в окремому staging-проєкті його активують одноразово через SQL-консоль власника:

```sql
update public.profiles
set role = 'admin', status = 'active'
where id = '<auth-user-uuid>';
```

Після цього адміністратор налаштовує TOTP під час першого входу. Production-користувачів і реальні дані не створювати до завершення staging-перевірки та окремого підтвердження власника.
