# Перевірка staging-версії 0.2.13

Дата перевірки: 20 вересня 2026 року.

## Що виправлено

- У плануванні тренера текстове поле організаційної потреби замінено погодженим переліком: «Підготовка поля», «Автобус», «Оператор», «Лікар», «Документи», «Інше».
- Перелік доступний для тренування, чемпіонату області, чемпіонату України і турніру. Для «Інше» обов’язково вводиться уточнення.
- Невдала спроба створити накладання більше не записується як постійна ситуація для адміністратора. Старі технічні записи конфліктів очищено, а адміністративний план, звіт та експорт додатково їх не показують.
- Виправлено неоднозначні Data API-зв’язки `coach_group_assignments ↔ profiles`, через які сервер повертав `PGRST201`, а розділ «Групи» помилково залишався порожнім.
- Картки всіх груп тепер формуються незалежно від наявності дітей. Помилка окремого показника не приховує саму групу.
- Для тренера підтверджено вхід лише за логіном і паролем. MFA викликається тільки для ролі адміністратора.

## Автоматична перевірка source

- `npm test`: 50 із 50 перевірок успішні.
- TypeScript: помилок немає.
- ESLint: помилок і попереджень немає.
- Перевірка staging-конфігурації: успішна.
- Production-збірка Next.js: успішна; маршрути `/` і `/password-reset/` сформовано.

Перевірки охоплюють ролі та RLS, календар, накладання, організаційні потреби, групи й воротарські групи, гравців, оплати, форму, інвентар, оголошення, методику, термінологію, оцінювання, імпорт, експорт, резервні копії, приватні файли та відновлення доступу.

## Перевірка безпеки

- Анонімний доступ до `profiles` і `coach_group_assignments` заборонений.
- Адміністративні операції й надалі вимагають ролі адміністратора та AAL2.
- Тренерські операції обмежені призначеними групами й працюють на AAL1, тобто після входу за логіном і паролем.
- Supabase Advisor не виявив таблиць без RLS. Наявні попередження щодо публічних RPC перевірено: це навмисні прикладні точки входу з внутрішньою перевіркою користувача, ролі або групи.
- У конфігурації Supabase залишається рекомендація ввімкнути перевірку паролів за базою скомпрометованих паролів; вона не впливає на виправлені сценарії.

Production не змінювався. Зміни призначені тільки для staging.
