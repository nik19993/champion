# Перевірка staging версії 0.2.4

Дата перевірки: 18 вересня 2026 року.

## Середовище

- Supabase-проєкт: `champion-staging` (`dlbombpmemdgkimbkuct`).
- Регіон: Frankfurt (`eu-central-1`).
- PostgreSQL: 17.
- У staging немає реальних даних дітей, контактів батьків, оплат, фото чи документів.
- Окремий owner-only тестовий Sites-проєкт розгорнуто після явного підтвердження власника; основний приватний сайт не змінювався.

## Застосовано до staging

- 21 послідовна міграція, версії яких зафіксовано в репозиторії.
- 35 прикладних таблиць; RLS увімкнено на всіх.
- 21 група: U6, U7, U8A–U15B та «Воротарі A/B/C».
- 318 активних навчальних завдань U6–U15 і 110 активних термінів.
- Довідник `evaluation_metrics` для тестування фізичної підготовленості та складових ігрової діяльності.
- Серверна перевірка, яка приймає результати лише для активного показника правильного типу та зберігає канонічну назву.
- Edge Functions `admin-users`, `file-validate`, `import-preview`; усі активні й вимагають JWT.
- Актуальні TypeScript-типи фактичної staging-схеми.

## Автоматизована перевірка

- 54/54 pgTAP-перевірки виконано без помилок безпосередньо в staging; кожний файл працював у транзакції з `rollback`.
- 35/35 локальних контрактних тестів — пройдено.
- ESLint — без помилок.
- TypeScript — без помилок.
- Next.js production-збірка зі staging URL та publishable key — пройдено.
- Транзакційний тест підтвердив RLS довідника оцінювання, нормалізацію назви й одиниці та відхилення показника неправильного типу.

## Контроль безпеки

- Таблиць без RLS: 0.
- Табличних прав ролі `anon`: 0.
- Виконуваних роллю `anon` прикладних RPC: 0.
- Публічних Storage bucket: 0.
- Неіндексованих зовнішніх ключів: 0.
- Дев’ять `SECURITY DEFINER` RPC залишаються доступними тільки автентифікованим користувачам навмисно; кожна операція перевіряє активний профіль, групу або адміністратора з MFA `aal2`.

## Що ще потрібно перед пілотом

1. Власник має визначити адресу першого staging-адміністратора; пароль не створюється й не передається без цього рішення.
2. Потрібно створити лише синтетичні облікові записи та пройти браузерні сценарії тренера й адміністратора з MFA.
3. Потрібно перевірити PDF/DOCX, реальний XLSX, друк, offline/online присутність, завершення signed URL і повний інтерфейс на ширині 360 px.
4. Формати змагань слід заповнювати лише після фіксації чинного первинного документа УАФ.
5. Приватний staging frontend уже розгорнуто без зміни аудиторії. Перед будь-яким production-розгортанням потрібне нове окреме підтвердження власника.

До production нічого не застосовувалося.
