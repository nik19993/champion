# Аудит відповідності вимогам — 18.09.2026

## Висновок

Production-каркас правильно переносить погоджену структуру застосунку на Next.js, TypeScript і Supabase та вже містить усі основні модулі. Код проходить lint, перевірку типів, 35 контрактних тестів і staging production-збірку. Staging-база активна, має 21 групу, 318 навчальних завдань, 110 термінів, 2 структури занять і 9 структурних кроків. Додано керовані адміністратором довідники тестування фізичної підготовленості та складових ігрової діяльності, серверну перевірку цих довідників і 30-хвилинне завершення неактивної сесії.

Застосунок ще не можна вважати готовим до щоденної роботи школи: у staging немає користувачів і повного наскрізного набору тестових даних; не виконані браузерні сценарії під ролями тренера й адміністратора; формати змагань груп ще не заповнені перевіреними первинними джерелами УАФ. Окремий owner-only тестовий Sites-проєкт уже працює із Supabase staging; основний сайт не змінено.

## Контрольна база

- технічне завдання «ЧЕМПІОН», редакція 1.0 від 16.09.2026;
- архітектура «ЧЕМПІОН», версія 1.0;
- усі пізніші погоджені уточнення з розмови, зокрема воротарські групи A/B/C, назва лише «ЧЕМПІОН», довідники оцінювання та наповнення методики;
- код версії 0.2.3 і фактичний стан Supabase staging `champion-staging`;
- чинний приватний Sites-проєкт без зміни його аудиторії.

Позначення: **Виконано** — функція є в коді та має серверне обмеження; **Частково** — реалізація є, але потрібна наскрізна перевірка або доповнення; **Не виконано** — погоджена функція відсутня.

## Перевірка безпеки staging

- проєкт `champion-staging` — `ACTIVE_HEALTHY`, PostgreSQL 17;
- 0 публічних bucket;
- 0 таблиць без RLS;
- 0 прав Data API для `anon`;
- 0 виконуваних `anon`/`PUBLIC` функцій застосунку;
- 9 `SECURITY DEFINER` RPC доступні лише `authenticated`; кожна має перевірку активного профілю, групи або адміністратора з `aal2`;
- Security Advisor показує попередження саме про ці 9 навмисно відкритих RPC. Це не автоматично вразливість, але їхні перевірки мають залишатися в регресійних тестах;
- Performance Advisor не знаходить неіндексованих зовнішніх ключів. Він показує невикористані індекси на порожній staging-базі та кілька дозволених RLS-політик на тих самих таблицях; видаляти індекси або механічно об’єднувати політики до пілотного навантаження не слід.

## Послідовність усунення розбіжностей і підключення

1. **Виконано:** додано довідники тестів фізичної підготовленості та складових ігрової діяльності, RLS, UI адміністратора й перевірку імпорту.
2. **Виконано:** уніфіковано назви «Тестування фізичної підготовленості» та «Складові ігрової діяльності».
3. **Виконано:** додано 30-хвилинний idle sign-out із попередженням перед виходом.
4. **Виконано:** перенесено міграцію словника й seed методики, застосовано міграції staging та повторно згенеровано TypeScript-типи.
5. Створити синтетичні staging-профілі адміністратора/тренерів і тестові дані для наскрізної перевірки.
6. Пройти браузерні сценарії: MFA, RLS двох тренерів, календар/конфлікт, присутність online/offline, оплати, форма, інвентар, PDF, XLSX, друк і 360 px.
7. **Виконано:** production UI зібрано з browser-safe staging URL/publishable key.
8. **Виконано після окремого підтвердження власника:** staging-версію розгорнуто в owner-only тестовому Sites-проєкті; основний сайт не змінено.
