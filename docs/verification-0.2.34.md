# Перевірка 0.2.34 — 26 листопада 2026 року

У наявному розділі адміністратора «Календар» додано дві внутрішні вкладки:
«Календар основних груп» і «Календар локацій». За замовчуванням відкрито
основну. В ній залишилися події вікових та воротарських груп; у другій —
події груп із `group_kind=location`, зокрема Junior.

Запит календаря додатково читає `groups.group_kind`. Класифікація події
використовує тип її групи, тому тренер із призначеннями в обох напрямах
не змішує ці календарі. Для історичних подій тип читається з приєднаної
групи, навіть якщо її немає в активному переліку. Для старих неповних
записів є перевірка за каталогом груп; невідомі історичні записи
залишаються в основному календарі.

Діапазон і формат 7/10 днів або місяця зберігаються при перемиканні.
Фільтри групи, тренера, типу, майданчика та скасованих подій незалежні
для кожної вкладки. Групи й тренери у списках відповідають вибраному
календарю; для локацій майданчики обмежені пов’язаними локаціями та
майданчиками їхніх подій. Обидві вкладки використовують одне завантаження
подій і чинне автоматичне оновлення, пагінацію та перевірку повноти.

Чинні події відкриваються через попередній обробник деталей. Не змінено
таблиці, дозволи, бронювання, події, призначення, розклади чи профіль
тренера. Стилі нової пари вкладок дозволяють побачити обидві назви
на вузькому екрані без горизонтального прокручування.

Перевірки:

- 212 автоматичних тестів, TypeScript і production build пройшли.
- Нові перевірки поділу охоплюють тренера обох напрямів, воротарів,
  історичну локацію без активної групи та старі неповні записи.
- 26 ізольованих браузерних перевірок: початкова вкладка, окремі події
  й списки фільтрів, незалежне збереження фільтрів, відкриття події за
  чинним ID, спільний період, новий запис після оновлення, приховування
  скасування без коментаря, помилка оновлення та порожній календар.
- Обидві вкладки й календар перевірені на 320, 360, 390, 768 і 1280 px.
  Запити тестового адаптера лише читають синтетичні дані.

Ручний вхід реальним адміністратором не виконувався. Зміна не потребує
міграції бази даних або повторного внесення тренерами своїх подій.
