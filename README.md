# Клуб Чемпіон — робочий застосунок 0.2.36

Це повний редагований вихідний проєкт застосунку Клубу Чемпіон, відновлений з погодженого прототипу та послідовно оновлений у source. Поточна staging-збірка розгортається лише приватно; production не змінюється без окремого підтвердження власника.

## Уже реалізовано

- Next.js + TypeScript із статичним export для Sites;
- адаптивна жовто-чорна дизайн-система, надана емблема клубу та заголовок лише «ЧЕМПІОН»;
- реальний email/password-вхід через Supabase Auth;
- відновлення пароля;
- обов’язковий TOTP/MFA для адміністратора;
- базові таблиці профілів, груп і призначень тренерів;
- 25 повноцінних груп: U6, U7, U8A–U17B та «Воротарі A/B/C»;
- призначення одного тренера до однієї або кількох вікових чи воротарських груп;
- календар тренера з часом за Києвом, події всіх закріплених команд, відвідування до/під час/після події та офлайн-черга; після присутності тренування одразу відкривається окремий крок жовтих карток без втрати контексту події; редактор події автоматично відновлює незбережену чернетку;
- гравці з пріоритетним показом контактів батьків одразу після фото й основної інформації, оплати лише «оплачено»/«не оплачено», коротка характеристика тренера та форма; текстові зміни й запити форми мають локальні чернетки;
- методика: пошук і редагування термінів, програма занять, структура тренування та довільні розділи загальної методичної бібліотеки;
- 349 погоджених завдань нової редакції: 284 для U6–U16 та 65 для воротарських груп A/B/C; кожна вікова категорія має власний набір, U17 — власні завдання тренера. Історичний seed містить попередню редакцію; актуальне наповнення встановлюється окремим кроком релізу. Словник доступний усім тренерам незалежно від віку;
- керовані адміністратором довідники тестування фізичної підготовленості та складових ігрової діяльності, а також сумісний Excel-імпорт результатів із датою в таблиці або спільною датою в інтерфейсі;
- інвентар груп із незалежними дозволами на кількість та втрати/придбання, чітким станом збереження, локальним відновленням змін і скасуванням останнього збереження;
- адміністративні План, Групи, Форма, Керування, звіти, імпорт і експорт; наявні поля та майданчики можна редагувати, зміни форми мають виразний стан збереження й скасування; PDF-звіти завантажуються як файли, а за відсутності записів містять повідомлення «Дані не внесено»;
- пакетний імпорт CSV/XLSX/DOCX підтримує гравців, фізичні тести, ігрову діяльність, навчальні завдання й термінологію; в інтерфейсі є універсальні шаблони Excel і Word;
- оголошення можна адресувати окремим тренерам, віковим категоріям або конкретним групам, включно з «Воротарі A/B/C»;
- «Зірка місяця»: спільна тема для всіх груп, централізований перелік причин і анулювання помилкових жовтих карток лише для тренувань, контроль контакту з батьками, автоматичний недопуск після чотирьох карток і два різні переможці з єдиною назвою нагороди без загального рейтингу;
- експорт нагород за місяць в один PDF: дві вертикальні нагороди A5 для переможців групи на одному горизонтальному аркуші A4, автоматичне фото з профілю та повне блокування експорту з точним переліком гравців без фото; службова графіка вбудована у генератор і не залежить від окремих мережевих запитів;
- окремі дії «Заборонити доступ» і «Видалити тренера»; остаточне видалення прибирає Auth-акаунт, але зберігає історичні записи та передає майбутні події на перепризначення;
- RLS: тренер бачить лише призначені групи, адміністратор — усі після MFA;
- приватні Storage buckets;
- SQL RLS-тести, контрактні тести, lint, typecheck і CI;
- перевірена staging-база з мінімальними Data API-правами та індексами всіх зовнішніх ключів;
- згенеровані типи staging-схеми підключені до Supabase-клієнта;
- попередження та автоматичний вихід після 30 хвилин бездіяльності;
- окремі конфігурації staging та production без автоматичного deploy;
- відтворюваний і повністю видалюваний набір синтетичних staging-даних без адрес, телефонів чи доступного для входу тестового облікового запису.

## Оновлення наявного застосунку

Порядок і точний перелік SQL: [release/2026-10-24/README.md](release/2026-10-24/README.md). Merge PR сам по собі не застосовує SQL, не замінює матеріали та не публікує сайт. Не виконувати `db reset` або сліпий `db push` на чинній БД.

## Локальний запуск

Вимоги: Node.js 22.13+; для локального Supabase також Docker.

```bash
npm ci
cp .env.example .env.local
npx supabase start
npx supabase db reset
npm run dev
```

Після старту локального Supabase вставити локальні URL та publishable key у `.env.local`.

## Перевірка

```bash
npm run lint
npm run typecheck
npm run test
npm run build
npm run db:test
```

`db:test` потребує запущеного локального Supabase. Команда `npm run quality` виконує всі перевірки, які не потребують Docker.

## Перший адміністратор

Після створення першого користувача в окремому staging-проєкті його активують одноразово через SQL-консоль власника:

```sql
update public.profiles
set role = 'admin', status = 'active'
where id = '<auth-user-uuid>';
```

Після цього адміністратор налаштовує TOTP під час першого входу. Production-користувачів і реальні дані не створювати до завершення staging-перевірки та окремого підтвердження власника.

Документація: [тренеру](docs/trainer-guide.md), [адміністратору](docs/admin-guide.md), [розгортання](docs/deployment.md), [резервування й відновлення](docs/backup-restore.md), [відновлення source](docs/source-recovery-2026-09-19.md), [перевірка 0.2.24](docs/verification-0.2.24.md), [повний аудит вимог](docs/requirements-audit-2026-09-18.md), [середовища](docs/environments.md) та [межі безпеки](docs/security-boundaries.md).

## Групи локацій і відновлення доступу (0.2.25)

Окремі групи локацій A/B/C, закріплений зал тренування, призначення чинних
тренерів та фільтри звітів описані у [посібнику](docs/location-groups-and-recovery.md).
Форми розкладу та наявні заняття збережені. Механізм резервних MFA-кодів
використовує Supabase Auth; робоча перевірка цього шляху й доставлення
листа потребують участі власника. Персональні паролі та TOTP не змінювалися.

## Вкладки груп та надійність призначень (0.2.26)

У «Групах» за замовчуванням відкриті «Основні групи»; поруч є «Групи локацій».
Для призначення тренера додано обмеження очікування, перевірку невизначеного
результату та повідомлення в картці тренера. Діагностика й межі перевірки —
у [звіті релізу](docs/verification-0.2.26.md).

## Junior, майданчики локацій та «Зірка місяця» (0.2.27)

До категорій локацій додано Junior без наперед заданих вікових меж.
У «Майданчиках» приховані окремі зали локацій; спільні майданчики
основних груп залишаються видимими. У результатах «Зірки місяця»
додано вибір основних груп, усіх локацій або однієї локації.
Виправлено серверну перевірку кінця місяця, яка блокувала збереження
переможців. Деталі й перевірки — у [звіті релізу](docs/verification-0.2.27.md).

## Групи воротарів і видалення порожньої групи (0.2.28)

У «Групах» адміністратора три окремі вкладки: основні, локації та воротарі.
«Видалити групу» доступно після перевірки порожнього складу. Сервер повторно
перевіряє гравців, додаткові зарахування та розклад, завершує призначення
тренерів і прибирає групу з активних переліків зі збереженням історії.
Контрольні заняття 17:00–18:00 та 18:00–19:00 не мають накладання.
Деталі — у [звіті перевірки](docs/verification-0.2.28.md).

## Лічильники груп і активних гравців (0.2.29)

Збережено блок додавання групи й кнопку; прибрано лише його заголовок
та пояснення. У цьому самому рядку показано кількість груп і гравців
поточної вкладки. Біля «Групи» показано загальну кількість активних
гравців без повторного обліку воротарів. Перевірки описані
у [звіті релізу](docs/verification-0.2.29.md).

## Очищення тестового архіву (0.2.30)

За прямою вказівкою власника прибрано архівні тестові профілі та пов’язані
з ними тестові записи. Активні гравці та їхні записи збережені.
Резервна копія архіву видалена за вказівкою власника.
Дизайн і розташування лічильників не змінено. Перевірки —
у [звіті релізу](docs/verification-0.2.30.md).

## Заголовок груп із загальними кількостями (0.2.31)

Прибрано верхній напис про кількість груп клубу. Наявний рядок заголовка
показує «Групи N» та «Гравці M»: загальні кількості активних груп
і унікальних активних гравців. Числа беруться з актуальних даних.
Стилі й решта розділу збережені. Перевірки —
у [звіті релізу](docs/verification-0.2.31.md).

## Документи окремих тренувань (0.2.32)

Тренер бачить збережені матеріали при повторному відкритті власної події.
До вже створеного тренування можна прикріпити документ окремою кнопкою,
без повторного збереження бронювання. Вибір локального файлу і підтверджене
прикріплення мають окремі повідомлення. Після невдалої спроби прикріплення
повторна спроба використовує вже створену подію та перевірений файл.

Підтримуються PDF, DOCX, JPEG, PNG і WebP. Чинний ліміт із версії 0.2.33 —
1 МБ після автоматичного стискання. Старий DOC потрібно
зберегти як DOCX або PDF. Серверна перевірка файлів залишається обов’язковою.
Виправлено прикріплення до збережених власних завдань основних груп і
реєстрацію матеріалів призначених груп локацій. Чинне поширення стандартних
матеріалів через навчальне завдання збережене. Перевірки —
у [звіті релізу](docs/verification-0.2.32.md).

## Автоматичне стискання планів до 1 МБ (0.2.33)

Кожний новий файл тренування проходить спробу стискання, навіть якщо він
менший за 1 МБ. Обробка виконується у фоновому процесі браузера до передачі
у Storage. Зберігається менший із прийнятних варіантів. У Word перепаковується
DOCX та оптимізуються підтримувані вбудовані зображення; у PDF зберігаються
текст, векторні схеми й геометрія сторінок, оптимізуються підтримувані JPEG.
Растрове вкладення може бути перетворене у WebP. Є попередній перегляд
підготовленого файла та повідомлення про отриманий розмір.

Новий файл після обробки має бути не більшим за 1 000 000 байт. Вихідний
файл для спроби стискання може мати до 20 МіБ. Якщо отримати прийнятний
результат не вдалося, вкладення відхиляється з поясненням; тренування можна
зберегти без нього. Чинні документи залишені без змін. Ліміт перевіряється
також у Storage і серверному валідаторі. Перевірки й обмеження алгоритму —
у [звіті релізу](docs/verification-0.2.33.md).

## Календарі основних груп і локацій (0.2.34)

У розділі адміністратора «Календар» додано вкладки «Календар основних груп»
та «Календар локацій». Першою відкривається основна: вона містить події
основних і воротарських груп. Друга містить події груп локацій, включно
з Junior. Класифікація використовує тип групи; один тренер може вести
заняття в обох календарях. Вибраний період спільний, фільтри незалежні.
Дані, бронювання та видимість тренерського профілю не змінено.
Перевірки — у [звіті релізу](docs/verification-0.2.34.md).
