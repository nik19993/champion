# Перевірка 0.2.32 — 26 листопада 2026 року

## Виявлене та виправлене

Редактор власної події не запитував уже прикріплені документи. Тепер
перегляд та редактор використовують один компонент і перечитують збережені
зв’язки `event_materials` та матеріали навчального завдання. Помилка читання
показується з повторною спробою; вона не видається за відсутність документів.

Вибір локального файлу позначається як незавершене прикріплення. Для наявної
події додано окрему кнопку: прикріплення не записує `events` і не змінює
бронювання. Успіх підтверджується окремим читанням зв’язку файла з подією.
Після часткового збереження нової події редактор зберігає її підтверджений ID,
виключає її з перевірки власного бронювання і повторює прикріплення без другої
події. Перевірений файл повторно використовується при помилці зв’язування.
Чернетка створення очищається після підтвердження створеної події.

Дозволені розширення та ліміт 20 МБ перевіряються до запису події.
Для документів задано MIME за дозволеним розширенням, зокрема коли браузер
не визначає тип DOCX. Серверна перевірка сигнатури й активного вмісту
залишається без змін. DOC не додано до дозволених форматів.

Міграція `20261126202357_training_document_persistence.sql` виправляє
невідповідність: редактор викликав `attach_event_material` для власного
завдання основної групи, але RPC дозволяла лише воротарську групу.
Тепер перевіряються тренувальний тип події, призначення групи, власник
перевіреного файла та відповідність групи й віку. Публічний RPC став
SECURITY INVOKER з перевіреною реалізацією у private. Розширено наявну
політику реєстрації матеріалів для призначених груп локацій; гілка фото
та обмеження для інших груп збережені.

## Два звернення тренерів

За перевірений день 26 листопада не знайдено запитів реєстрації чи
завантаження документів від Валентина Білика та його збережених файлів
`task-documents`. У його профілі є збережені фото гравців; вони не є
документами тренувань. Точну дію та формат невдалої спроби за цими даними
встановити неможливо. Відсутні на сервері документи не відновлювалися.

Журнал PostgreSQL за 26 листопада, 05:37 UTC, зафіксував INSERT нової події
Романа Андрієшина з `23P01`: тренер зайнятий на U9B у ЗОШ № 26,
16:20–17:35 за Києвом. Це накладання на вже збережене заняття. Окрема
перевірка `venue_booking_conflicts` з виключенням ID редагованої події
повернула 0; без виключення — 1. Реальні події не редагувалися.

## Валідація

- 194 автоматичні тести, TypeScript та production build пройшли.
- 27 ізольованих браузерних перевірок календаря, редагування, видалення,
  скасування зі збереженням присутності, звіту та CSV пройшли. Адаптер
  сценарію приведений до чинної кнопки «+», віку завдання й параметрів звіту.
- 15 ізольованих браузерних перевірок документа: повторне відкриття і
  перезавантаження, невдале читання, часткове створення, повторне
  прикріплення без дублювання події або файла, MIME DOCX, відсутність
  горизонтального переповнення на 320, 390 і 1280 px.
- SQL-сценарій `0014_training_documents.test.sql` виконаний у транзакції
  з ROLLBACK: основна група, власне завдання, воротарі, локація,
  ідемпотентність зв’язування, відхилення неперевіреного/чужого файла,
  непризначеного тренера й нетренувальної події. Нові Auth-користувачі,
  об’єкти Storage чи облікові дані не створювалися.
- До міграції той самий сценарій відтворив відмову RPC для власного
  завдання основної групи. Після міграції сценарій пройшов.
- Після відкату тестів немає тестової локації чи подій 2098 року;
  кількість реальних файлів `task-documents` залишилася 8.
- Перевірка безпеки не додала попереджень; кількість публічних
  SECURITY DEFINER RPC у попередженні зменшилася з 17 до 16.

Ручний вхід реальними акаунтами тренерів і завантаження їхніх оригінальних
документів не виконувалися. Браузерні тести використовують локальні
синтетичні дані, а SQL-тести — лише транзакційні claims чинних працівників.
