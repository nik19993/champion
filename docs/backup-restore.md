# Резервне копіювання та відновлення

## Що зберігає застосунок

Кнопка «Адміністративна резервна копія» збирає робочі таблиці, шифрує JSON у браузері AES-256-GCM і завантажує файл `*.encrypted.json`. Пароль не надсилається на сервер і не може бути відновлений.

Ця копія доповнює, але не замінює керовані резервні копії PostgreSQL/Supabase: у ній немає Auth-паролів і двійкових Storage-об’єктів.

Підготовлене оновлення охоплює всі 46 робочих таблиць сумісної схеми, включно
з налаштуваннями сезону, історією груп і підтвердженнями обліку тренувань.
Читаються всі сторінки в порядку первинних ключів, звіряються точні кількості,
перевіряється чинний активний адміністратор із MFA до та після читання.
Помилка, дубль або неповний набір зупиняють створення файла. Немає завантаження
часткового JSON під виглядом завершеної копії.

Вміст має `schema_version: "1.5"`, `row_counts`, час початку й завершення,
`backup_scope: "application-tables"` та `full_recovery_backup: false`.
Послідовне читання через API не є транзакційним PostgreSQL snapshot: зміни
значень без зміни кількості не обов’язково будуть виявлені. Для узгодженої
повної копії потрібен окремий підтримуваний logical dump, Auth backup/config
і двійковий Storage snapshot. JSON не містить схеми, policies або Edge source.
Експорт запускається після застосування сумісних SQL-пропозицій; відсутня
нова таблиця спричинить явну помилку, а не її мовчазне пропускання.

## Регламент

- Щодня: керована резервна копія БД із політикою зберігання провайдера.
- Щотижня та перед кожним релізом: зашифрований адміністративний експорт і окремий контроль Storage.
- Щомісяця: пробне відновлення тільки в ізольований staging-проєкт.
- Пароль і файл зберігати окремо; доступ мають лише визначені власником адміністратори.

## Перевірка зашифрованого файла

```bash
CHAMPION_BACKUP_PASSPHRASE='<пароль>' npm run backup:decrypt -- \
  ./ЧЕМПІОН_backup_РРРР-ММ-ДД.encrypted.json \
  ./restored-backup.json
```

Команда не перезаписує наявний файл і створює результат із правами `0600`. Після перевірки незашифрований JSON потрібно безпечно видалити.

## Відновлення

1. Зупинити внесення змін та зафіксувати час інциденту.
2. Створити новий ізольований staging-проєкт тієї самої версії схеми.
3. Відновити керований database backup і Storage snapshot. Якщо використовується адміністративний JSON, розшифрувати його та імпортувати транзакційним серверним скриптом із вимкненим зовнішнім доступом.
4. Перевірити кількість груп, гравців, подій, відвідувань, оплат і зв’язків документів; виконати RLS-тести.
5. Лише після письмового підтвердження власника повторити погоджене відновлення у production.

Не імпортуйте адміністративний JSON через браузерний пакетний імпорт: він призначений для вибраних наборів даних, а не повного відновлення системи.
